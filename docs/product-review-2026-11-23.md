# 产品体验与机会评审：MyTranscript 桌面端

日期：2026-11-23 ｜ 视角：产品经理（增长 / 留存 / 差异化）

## 一句话结论

这不是一个"更好的播客播放器"，而是一个**能读、能查、能练的英语播客学习终端**。真正的护城河是「词级双语稿 + 逐词高亮 + 本机模型」，不是内容库大小。当前最该补的不是更多播放器功能，而是把 **任意播客 → 有稿 → 精听 → 输出** 这条链路补成闭环，并把已经存在但散落的学习工具打包成一条用户能坚持的日常路径。

## 0. 走查范围

实际构建并运行当前工作树，走过以下界面与动作：

- 首页、播客库、导入内置源、节目页、单集页、阅读/播放器（逐词高亮、底栏、侧栏笔记、播放到结尾）
- 发现页（本站目录 + 在线搜索入口）、搜索页（索引入口与空状态）、播放队列
- 统计与回顾、笔记、收听模式（界面/播完行为/睡眠定时/播放列表）
- 设置：播放设置、模块开关、文字稿与字幕、模型管理、外观与主题（11 套主题 + 自定义 CSS/HTML）、插件管理、数据管理
- 字幕中心、片段库、摘录本、学习中心（为走查临时启用）

未成功进入：无。走查中一度以为「下载管理」点不动，复核后确认是截图坐标换算导致的 3px 落点误差，路由本身正常（详见 P0-5）。

走查过程中改动的订阅、插件开关、主题与首页横幅均已还原；试听把 hwmym S4E6 的进度推到了结尾，如需恢复原来的 49:24，需要清掉这一条播放进度。

## 1. 用户与任务判断

目标用户不是"想找新播客的人"，而是**"想把英语播客真正听懂、学透的人"**。三类核心任务：

1. **泛听筛选**：这集值不值得听？讲了什么？——需要摘要、章节、难度、时长。
2. **精听拆句**：这一句没听懂，倒回去，看词、看译、听清。——需要词级稿、单句循环、查词、慢速。
3. **输出积累**：把词、句、观点带走，下次还能复习。——需要生词本、笔记、复习、分享、导出。

现有能力在 1 和 2 上已经有很好的零件，在 3 上有零件但没有流水线；最容易形成差异化的是 2 和 3，而不是再去堆 1 的曲库。

## 2. 能力盘点

| 层 | 已经很强 | 明显缺口 |
| --- | --- | --- |
| 内容 | 14 档内置节目、RSS/OPML、Apple/Podcast Index 搜索、收件箱 | 新源没有"订阅即转写"；推荐只有编辑目录 |
| 播放 | 倍速、睡眠定时、跳过广告/静音、队列、离线、迷你窗、托盘、完整快捷键 | 无 A-B 复读/单句循环；播放列表管理弱 |
| 阅读 | 词级双语稿、逐词高亮、点击跳转、未读弱化、字号/行距/宽度、查词、单句精听、全文查找 | 无说话人区分；术语表/人名纠错未产品化；无 PDF/打印导出 |
| 学习 | 生词本、到期复习、句子卡、填空、听写、整集总结、本集问答、CSV 导出 | 无跟读/发音；无学习计划与连续天数；AI 必须自备 Key |
| 系统 | 桌面字幕、全局快捷键、主题 token 化、插件机制、本地优先、数据导入导出 | 无账户/云同步/手机端；无社区与共享稿 |

## 3. 体验诊断（按优先级）

### P0：会直接伤信任或断主链路

**1）新订阅的节目没有词级双语稿，核心承诺断链。**
内置 14 档之所以好，是因为离线流水线已经产出了词级稿；但从"发现"或"添加 RSS"订阅一档新节目后，应用里没有转写入口，用户拿到的只是普通 feed，遇到听不懂的句子只能开实验性的实时识别。发现页却在用「双语词级文字稿」做卖点，预期会落空。
**方案已改为「下载时询问是否转写」**：不做订阅后静默排队——转写吃 CPU、可能跑几十分钟，订阅时替用户决定并不合适。现在整集音频下载完成后，如果这一集没有现成文字稿，会弹一次确认「要用本机模型整集转写吗」，选取消就只留音频；转写在下载管理里显示「转写中 42%」，完成后这一集可离线逐词跟读，重启后也能接回稿子。用户仍可在单集里随时手动预转写。

**2）学习中心默认不可用。**
学习中心顶部直接写着「AI 服务：openai · 还缺 Key 或模型」，此时"当前句学习卡 / 整集总结"都产不出内容。对主打"学英语"的产品，这是把新用户挡在门外。
建议：无 Key 也能完成一轮学习——本地词典释义、词频/难度、填空与听写、到期复习都可离线；只有"整集总结/自由问答"才要求 Key。更进一步，可内置一个 0.5B–1.5B 的本地小模型做摘要与出题，彻底去掉配置门槛。
**已改并实测**：学习中心在未配置 AI 时把主按钮换成「去配置 AI」，并明说"复习、生词本、填空和听写可以离线用"；句子卡/整集总结点击时先给方向，不再静默失败。

**3）退订是一键生效，且没有撤销。**
播客库卡片上的按钮写着"已订阅"，单击一次立刻弹出"已取消订阅。"——用户以为是进入管理，实际执行了破坏性操作。
建议：二次确认，或改成"管理中"；至少给 5 秒"撤销退订"的 toast。批量退订同理。
**已修并实测**：播客库的已订阅卡片改为「管理中」，点击进入节目页；所有退订入口（节目页「已订阅 · 退订」、站外「移除」）先弹确认，确认框写明"已下载的单集、笔记与收听进度不会删除"。真机验证：取消时订阅保持 1，确认后退订成功、订阅数归 0。

**4）插件"停用"不持久——复核后不成立，是走查误差。**
复核方式：用 WebView2 调试端口直接读 DOM 与 `enabled.json`。初始 `aria-checked=false`；点一下变 true 且写盘 true；再点回 false 且写盘 false；`reloadPlugins` 后左侧「学习中心」入口消失。停用/启用都持久，软重载也生效。
真实残留只有一个：插件给自己加的 `body.study-plugin-on` 类名在停用后没人清。宿主本来就支持 `claim()` 返回清理函数，插件没返回。**已修**：`study/main.js` 的 claim 现在返回清理函数，停用时移掉类名与 `data-study-plugin`。

**5）下载管理入口点击无响应——不是缺陷，是走查坐标误差。**
复核方式：`document.querySelector('[data-route="downloads"]').click()` 得到 `#/downloads`、标题「下载管理」，路由正常。之前两次"点不动"是因为截图坐标换算后落点比按钮高 3px，实际点在了上方「搜索」的底边。
产品层仍值得补的：下载页的空状态与磁盘占用展示。这属于 P1，不是 P0。

### P1：影响激活、留存或规模化

**6）搜索索引还是"手工作坊"。**
我这台机器上索引了 5 集，而库里仅 hwmym 就有 124 集；要搜全库必须手动点「索引全部订阅」，串行逐集跑，没有覆盖率、暂停、失败重试，也没有"哪些集可搜"的直观反馈。
建议：后台增量索引 + 进度/暂停/重试 + 按节目筛选；搜索页常驻「已覆盖 5/124 集」，并允许"只搜已索引"或"边听边索引"。

**7）统计只到"周报"，却叫"年度回顾"。**
页面只有最近 7 天柱状图和全时段节目排行，没有目标、连续天数、完成率、年度回顾，也没有可分享的卡片。
建议：先做"本周目标 + 连续天数 + 年度卡"三件套；年度卡复用现有 1080 分享画布，天然适合传播。

**8）首启没有三步路径。**
0 订阅时，首页仍然在讲品牌，播客库只给两个按钮；导入弹层是一张 7 档节目的清单，没有搜索、没有"为什么选它"、没有难度/时长信息。
建议：首启固定三步「导入一档 → 试听 60 秒 → 看一句稿」，默认勾选一档 20–30 分钟的短集节目；导入弹层给每档一句"适合谁"+ 单集时长中位数。

**9）跨设备同步靠手工搬运 JSON。**
设置 → 数据管理只有"导出 JSON / 从文件同步 / 清除本地数据"。桌面端文案还写着"只影响当前浏览器"，与产品形态不符。
建议：先做"扫码迁移"（桌面生成二维码，手机扫码接收订阅/进度），再考虑 Supabase/WebDAV 可选同步；桌面端把"浏览器"改成"本机"。

**10）桌面字幕被埋没。**
字幕中心里最独特的能力是"开始桌面字幕"——把系统里任何声音转成字幕。但当前状态是"未开始"、没有权限/隐私说明、没有效果预览，用户不会知道这是杀手锏。
建议：首次使用向导（选择应用 → 试 10 秒 → 说明音频不出本机）；在字幕上支持双击取词入生词本。

### P2：值得做，但不紧急

**11）分享卡只有一张固定深色 1080 方图。**
已有引用卡生成能力，但没有封面、波形、二维码、时间深链；别人扫到图也回不到原句。
建议：3 套模板（深色/纸张/极简）+ 深链 + 二维码；周报卡复用同一套画布。

**12）切换内置主题会静默停用自定义主题。**
有 toast 提示，但没有"一键还原"；自定义 CSS 是重度用户的资产。
建议：切主题前给"临时预览 / 保留自定义"两个选项，或在主题卡上标注"将停用自定义主题"。

**13）单集简介被 feed 截断，没有"查看完整/原文"。**
不是应用截断，而是源里就断在半个单词；用户会以为是产品坏了。
建议：折叠展示 + "查看原始简介"链接，并在节目页保留完整简介。

## 4. 新功能提案（按"学习闭环"排序）

### A. 精听四步：把现有零件装成一条流水线（成本 S，优先级最高）

**盲听 1 遍 → 看稿 1 遍 → 跟读 1 遍 → 复述/填空 1 遍**，每步 2–3 分钟，自动生成一个 8–10 分钟的"精听 session"。

不需要新引擎：逐句跳转、单句精听、双语稿、填空、听写、笔记、生词本都已存在，缺的只是**编排、计时、完成态和下一步推荐**。这是投入产出比最高的一件事，也能立刻把"学习中心"从工具箱变成课程。

### B. 影子跟读实验室（成本 M，差异化最强）

选中一句 3–15 秒的音频，用户录音，做三件事：

- 波形/能量对齐，标出"漏读、晚起、语速过快"；
- 用本机 ASR 对比原句，给出漏词率与卡顿点；
- 同一句可回放"原声 / 我的 / 并排"。

配"每日一句"和连续天数。它把产品从"看得懂"推进到"说得出"，是英语学习产品里最稀缺的一环，而且完全可以用本机模型完成，符合本地优先的定位。

### C. 每日 15 分钟"学习电台"（成本 M，留存抓手）

每天自动混编一条 15 分钟音频：3 段今日 clips（来自继续收听/收藏/推荐）+ 5 个到期生词的原句 + 1 个填空。用 TTS 做 20 秒串场，听完直接进入复习。

它解决的是"打开应用不知道干什么"的问题，把碎片时间变成固定习惯；也能自然带动睡眠定时、离线下载和连续天数。

### D. 语义电台 / 观点地图（成本 L，长期壁垒）

用户输入"AI 会不会让教育更不公平"，跨 14 档节目检索相关片段，生成一条 20 分钟的主题播放列表，每段带时间戳与原句。进一步把高频主题做成"观点地图"：同一话题下不同嘉宾的立场对比。

技术上先做"关键词 + 向量"混合检索，索引 14 档已有稿；这会把"内容库小"从劣势变成优势——垂直、可引用、可追溯。

### E. 任意播客转写流水线（成本 L，决定天花板）

订阅即排队转写，节目页显示覆盖率、预计时间、失败重试；对已有 `podcast:transcript` 的源优先复用，没有的走本机 ASR + 对齐。转写完成后自动进入搜索索引与学习功能。

这是把"14 档精品"扩展到"任意播客"的关键，也是收费点最清晰的地方（转写时长/并发）。

### F. 共享片卡 2.0 + 深链（成本 S–M，增长杠杆）

引用卡加上封面、波形、二维码与 `#/episode?t=123` 深链；一键分享到小红书/X/微信。别人扫码打开就能落到原句，形成"内容 → 安装 → 再分享"的回路。

### G. 跨设备账户 + 手机伴听（成本 L，场景补全）

订阅、进度、生词、笔记、主题同步；手机 PWA 扫码接着听，支持离线包。先做"扫码迁移"过渡，再上账户。没有手机端，"通勤听 + 桌面精读"这条最强使用场景是断的。

### H. 说话人感知稿（成本 M–L，阅读体验升级）

访谈类节目自动区分 SPEAKER 1/2，支持"只看某人"、按人着色、按人检索；配每档节目的术语表/人名表，减少 "Lily's emba" 这类断句与错名。

### I. 桌面取词 Pro（成本 M，系统级差异点）

在桌面字幕上双击单词：即时释义、发音、加入生词本；支持 YouTube/Netflix/网课。音频与识别都在本机，明确隐私边界。它能把"学英语"从播客扩展到所有英文视频。

## 6. 成功指标

- **首启激活**：导入 → 播放 → 打开文字稿，60 秒内完成的比例 ≥ 60%
- **留存**：7 日留存 ≥ 25%；每周精听 ≥ 30 分钟的用户占比 ≥ 30%
- **转写**：新订阅 24 小时内词级稿覆盖率 ≥ 80%，失败率 < 5%
- **学习**：每活跃用户每周 ≥ 2 次复习或跟读；精听四步完成率 ≥ 40%
- **分享**：每 100 活跃用户 ≥ 3 张分享卡，扫码回流 ≥ 10%
- **搜索**：索引覆盖率 ≥ 90%，零结果率 < 15%

## 7. 明确不做

1. 不做排行榜、社交信息流、评论区——在账户与社区之前，只会增加噪音。
2. 不追 CarPlay/Android Auto——手机端还没有，先做 PWA。
3. 不把 AI 聊天做成主入口——AI 只出现在"解释这句 / 出题 / 总结"三个动作上。
4. 不继续加主题皮肤——先把现有 11 套的排版一致性做稳，主题是放大器不是产品。
5. 不为"大而全"接入视频平台——先把播客这条链路做深。
