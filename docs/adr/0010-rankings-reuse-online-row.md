# 榜单复用在线搜索的行组件，样式只加在基础层

排行榜（`docs/rankings.md`）要同时活在 7 个内置档和 9 套随包主题里。决定不新建一套榜单专属
视觉，而是复用发现页已有的 `.tabs`、`.online-chips`、`.online-row`、`.btn` 原语；唯一新增的
`.chart-rank` 写在 `site/player.css`，只用 token 取色。9 个 `themes/*.css` 一行不改。

## Considered Options

- **新建榜单卡片 + 逐主题覆盖**：视觉上限更高，但 16 档要各写一遍，主题一改就漂；维护成本不可接受。
- **把榜单做成插件页**：插件可以自带 UI，但要新增贡献点与授权模型；榜单是默认可见的核心发现入口，不该押在插件上。
- **在行内直接写主题判断**：按 `data-theme` 分支换样式，等于把主题逻辑塞进业务代码，后续加主题必改 JS。

## Consequences

- 榜单的观感基本等于当前主题对发现页/在线搜索的处理；8 套包对这部分是零覆盖，会直接继承基础层。
- 新增的唯一基础类 `.chart-rank` 会影响所有主题，所以只允许用 token，不允许写死颜色。
- 主题若想强化榜单，应在自己的包里 opt-in，而不是反过来要求榜单适配每套主题。
