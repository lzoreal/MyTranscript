# 官方插件与第三方插件走同一套导入与授权

Status: accepted（2026-11-20）

本机默认不带任何插件：首次安装不向插件目录铺文件，也不自动启用。官方功能插件放在仓库的
`apps/windows/builtin-plugins/`，作为随仓库提供的**可选手动导入包**；用户导入后与第三方插件走
完全相同的流程：默认停用、首次启用弹应用内授权、文件指纹变化后重新授权。

插件身份不再按“所在目录”隐式判定。当前实现里 `builtin` 恒为 `false`，官方插件也要授权；
真正的官方只读目录与免授权信任分层没有实现，不在本期范围内。

两端共用同一套公共契约：`plugin.json` 声明式清单、`MyTPlugins.define`、贡献点注册表。
官方插件同样要通过清单校验与贡献点校验，没有额外特权。

## Consequences

- 默认状态保持“无插件、原生可用”：首页、库、下载、设置由宿主兜底，播放与下载收听历史不依赖插件。
- 官方插件的升级仍跟仓库/安装包走，但导入动作由用户完成；用户也可以手改导入后的副本，指纹变化会触发重新授权。
- 设置页只有一个插件列表，不区分官方/第三方来源；列表里显示每个插件的授权状态与错误。
- 原“官方只读目录默认启用”的方案被否决，原因是与“本机不再自带插件、由用户手动导入”的产品要求冲突。
