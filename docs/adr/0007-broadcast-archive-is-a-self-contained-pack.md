# 档案室档做成自包含包卡，不新增骨架、不改共用渲染器

用户要一档"整间房间"的拟物主题（广播档案室）。但主题模型只有一层：当前主题就是一个 id，
包卡一旦选中就整套注入 CSS 并把 `html[data-theme]` 写成包 id，内置档的版面规则一条都不命中，
所以**切换是即时的**；骨架变体（`src/skeletons/<id>`）目前只能靠 `?skeleton=a|b|c` 预览，
选了就会关掉自定义主题并且必须重载；而首页卡片 markup 由共用渲染器 `07-routes-pages.js`
统一产出 `.pod-card` / `.continue`，所有档共用。因此把整档作为**一套自包含包卡**交付
（`themes/broadcast-archive.css` + `.json`，`scope` 取 `rail`），房间结构由 CSS 在现有挂载点
（`#homeRecommended`、`#homeRecent`、`#homeContinue`、`#homeStats`）里用 grid 成型，
不加骨架、不动渲染器。

被否掉的两条：**新增骨架变体**——能真换 DOM，但切档要重载、要重跑骨架 id 回归、
还要先把自定义主题摘掉；**改渲染器出档案格 markup**——会波及现有每一档，JS 与 CSS 的边界也破。

后果：视觉上限被现有 DOM 卡住——档案格只能在原容器里重排，格内结构靠伪元素与背景拼，
不能新增语义节点；控制台抬高要动 `--bottom` 并验证不遮首页；移动端必须降级为单列。
