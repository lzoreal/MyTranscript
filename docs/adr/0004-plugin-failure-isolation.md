# 插件失败时壳先起并按槽位降级

Status: accepted（2026-11-20）

宿主启动顺序固定为：先渲染壳骨架与原生回退，再发现、校验、排序和激活插件。插件加载状态按 `discovered → validated → authorized → loaded → active` 推进；任何一步失败进入 `blocked / error / quarantined`，回收该插件已注册的页面、槽位、命令、provider、监听和样式，对应槽位回退原生实现或空态。

插件页面在激活前被路由到时显示骨架而不是空白；超时进入错误页，允许重试。单个官方插件失败只降级它负责的区域，不拖垮首页或整个壳。依赖按 `requires` 的 semver 范围拓扑排序；缺依赖进入 `blocked`，依赖环直接拒绝。

## Consequences

- 不再有“插件全成才启动”或“一个插件报错就黑屏”的路径。
- 官方插件也要在失败隔离测试里验证回收，不能依赖启动顺序掩盖问题。
- 直接替换旧宿主后没有运行时双壳；发布层必须保留上一版安装包和数据兼容作为回退。
