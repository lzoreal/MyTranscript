# 贡献点上下文按类型收窄，调用可取消，payload 独立版本化

Status: accepted（2026-11-21）

## 背景

2.1 的 `ctx` 是一份所有贡献共享的冻结合集：菜单、搜索源、导入器拿到的能力组和整页插件一样多，
`subtitles` / `study` / `settings` 越堆越多。每次加功能只能往同一个对象上追字段，公共 API 持续膨胀，
且没有版本锚点区分“这版插件到底用了什么”。

同时，宿主对插件只有 10 秒超时和请求代次：超时只是不再等待，代次只是丢弃结果，插件里的 `fetch`、
轮询和等待循环在停用、切页、换搜索词之后仍然在跑。

## 决策

1. **按贡献类型装配 `ctx`**（`host/context.js`）：每种贡献只拿一套档案，`api` 也按类型投影。
   收窄不是删除能力，而是让新插件只能用到自己那种贡献真正需要的服务。
2. **版本兼容层**：`2.0/2.1` 清单继续拿 2.1 的完整上下文；只有声明 `2.2` 的插件走窄档案。
   收窄因此不是破坏性变更，`3.0` 之前不需要 `compat` 目录。
3. **payload 独立版本**：页面、槽位、设置分区、搜索结果、菜单等各有版本号，插件通过
   `ctx.payloadVersion` 读取；槽位锚点可覆盖，搜索结果可用 `{ version, items }`，旧形态继续接受。
4. **真取消**：每次贡献调用、页面渲染、槽位挂载、命令执行都带 `AbortSignal`；停用、启动失败、
   页面销毁、槽位卸载、新搜索都会 abort。取消统一为 `AbortError`，不写插件诊断；超时仍是故障。
5. **UI 适配独立**：菜单、导入器、搜索源、主题的 DOM 操作搬进 `host/ui-adapters.js`，宿主只提供 port
   （注册表查询、调用分发、搜索代次、主题前置动作）。宿主不再认识 `themeGrid`、`pluginMenuPop` 这些结构。

## 代价

- 需要维护一张“类型 → 上下文组 / api 字段 / payload 版本”的契约表，新增贡献点时同步更新，测试锁住。
- 需要一条 2.1 → 2.2 的兼容档案，旧插件行为不回归；新插件升级时可能发现某个组不在档案里，需要换贡献
  类型或显式申请。
- 取消依赖插件尊重 `ctx.signal`；不检查信号的插件仍会跑完，宿主只能保证结果不回写。要强制隔离仍需
  Worker / iframe + RPC，当前只在需要运行不可信第三方时才值得承担。

## 后果

- `HOST_API_VERSION` 升到 `2.2`，契约测试快照同步更新。
- 测试宿主同时模拟 `ctx` 与取消：槽位卸载/停用会 abort，`tests/host-context.test.mjs` 与
  `tests/host-aborts.test.mjs` 锁定行为。
- 清单校验可以脱离宿主运行，示例插件 `examples/plugins/search-echo` 持续验证 2.2 契约。
